# Dutch Vocabulary Trainer V2.4 — Stable Core test plan

## Automated checks

### Self-tests
Run from the repository root:

```bash
node tests/v2.4-self-tests.js
```

The self-test suite is dependency-free and checks the application contracts, required modules, database schema, persistence APIs, pack ownership, exercise types, practice flow, selection persistence, import validation, and the Packs refresh wiring.

### Browser smoke test
The CI browser test runs against the real `index.html` served from localhost. It verifies:

1. Application initialization completes.
2. Home screen is active after startup.
3. Dashboard navigation works.
4. Word Packs navigation works.
5. Active-pack selector and Installed Packs container exist.
6. Settings navigation works.
7. History navigation works.
8. Practice setup opens and closes.
9. Navigation can return to Dashboard.
10. No browser console/page errors occur during the smoke flow.

Run locally after installing Playwright:

```bash
npm install --no-save playwright@1.55.0
python3 -m http.server 8000
node tests/v2.4-browser-smoke.cjs
```

## CI policy

`.github/workflows/v2.4-tests.yml` runs the dependency-free self-tests on pushes and pull requests to `main`. The browser smoke test runs only after self-tests pass.

## Scope boundary

This milestone deliberately does **not** change the application data model. IndexedDB schema 3 and the existing vocabulary/backup formats remain the source of truth.

The smoke test is a fast regression gate, not a replacement for the later full exercise-behavior test suite. The next testing expansion should add deterministic tests for DB operations, pack import/remove/select behavior, scheduler calculations, mastery updates, and complete practice sessions.
